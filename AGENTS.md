# AGENTS.md

- After making changes, **never run `templ generate` / `go tool templ generate` and never manually rebuild `*.min.js` component assets**, since both JS minification and generated `_templ.go` files are handled automatically by the normal development workflow (`task dev` / watchers).
- **`static/sitemap.xml` and `static/llms.txt` are generated files, not hand-maintained ones.** Both are derived from source that changes on every new component or route (`registry.json`, `cmd/docs/main.go`), and both get regenerated automatically by the Dockerfile on every build, so no local action is needed after adding a component or route. Know why this matters though: a stale sitemap means the build-time `highlight-gen` crawl never visits a new page, so its code blocks silently render as plain unhighlighted text in production only. `task dev` always hits the live shiki service and can't reproduce that failure mode locally, so a page rendering fine on `localhost` is not proof it highlights correctly in prod. The same staleness class hit `llms.txt` once already (a component missing from it for months), caught only by someone asking why it wasn't there.
